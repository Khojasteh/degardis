### Seeing what the compiler decided

`inspect` reports what a source compiles to. It runs exactly the checks
`validate` runs, over the same compilation, and sets the same exit status;
`--only` and `--all` choose what is printed, never what is checked.

`--only composition` answers why a page carries what it carries, and in what
grouped order it renders:

```console
degardis inspect my-skill --only composition
```

```text
review-draft -> references/tasks/review-draft.md
  direct      cite-the-source, audience, order-findings
  required    source-material
  concept     audience, source-material
  constraint  cite-the-source
  guidance    order-findings
```

`direct` is what the task named, and `required` is what those units pulled into
the closure. The kind rows give the knowledge order that renders under each
present subsection.

### Reading a row

Every report opens with `skill`: the name, version, title, root, description
length, the tasks a request is routed to, one count per selected content key,
and a `size` row giving generated bytes against the root, task, principle, and
guide budgets.

| Row | Shape |
| --- | --- |
| `tasks` | `ID "TITLE" PAGE BYTES N knowledge`, then the goal, one `when` row per recognition cue, and the guides the task names |
| `knowledge` | `ID kind=KIND BYTES requires=... tasks=...` |
| `principles` | `ID PATH BYTES -> PLACEMENTS page=PAGE` |
| `guides` | `ID PATH BYTES [ACTIVATION] -> TASKS` |
| `outputs` | every file a build would write, with its generated size and mode |
| `diagnostics` | `SEVERITY CODE LOCATION MESSAGE` |

An id is a file stem, so a row names the file to open. On a `knowledge` row,
`tasks` is every task page carrying that unit: a unit two pages carry is
compiled into both, which is what makes each page complete. On a `principles`
row, PATH is the file in your skill that states the principle, PLACEMENTS name
the skill or task owners with any condition they state, and PAGE is the page
those references open. A `guides` row's condition belongs to the guide itself,
for every task that names it, and an absent one applies unconditionally.

This report is the only machine interface. A build writes the bundle and nothing
beside it — no plan, no closure, no source map, no coverage file.

### Reading a page without building

`--page` prints what a build would write to one generated page, and writes
nothing itself:

```console
degardis inspect my-skill --page SKILL.md
degardis inspect my-skill --page references/tasks/review-draft.md
```

A path is the page's own place in the bundle: `SKILL.md` for the root, and for
anything else the page the report above names beside the task, principle, or
guide it belongs to. Repeat the option, or separate paths with commas, to read
several in one run. Each page follows the report, its lines indented by two
spaces, once for every selected skill; a path one skill does not generate is
reported as unavailable, and a path none of them generates lists the pages that
do exist and fails the run.

### Quality measures

`--only quality` measures the compiled result. None of it authorizes the compiler
to change anything: the numbers are there for you to act on.


- **Orphan knowledge** is material the bundle carries none of.
- **Near-duplicate** pairs are usually the same thing written twice.
- **Duplicated bytes** is what task closure cost — normal and often right, but
  a large number over few tasks can mean two tasks are really one.
- **Startup bytes** is the generated root the agent loads for every request.
- **Minimum read bytes by task** adds that root to each generated task page. It
  measures the baseline read before any separately loaded principle or guide.
  **Headroom** is the smallest unused margin under the root or task-page byte
  budget; a low value identifies the page closest to refusing a future edit.

### Saying which source a result came from

```console
degardis inspect my-skill --only identity
```

Among the identity rows is a source fingerprint: one digest over the manifest,
every file it selects, and the compiler's version, normalized so a Windows
checkout and a Linux runner agree on it. Quote it beside any result you keep.
